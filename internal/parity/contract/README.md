
The board presents the same parent, phase and member IDs in both interfaces. The
browser nests children in expandable parent cards; the terminal keeps indented
child rows visible in its read-only table because it has no card-expansion cursor.
Both boards give an unfinished task its time in its column (the card's figure and the end of the terminal's row). The browser also
rings a card whose owner is working on it now, or that the stall detector named, and writes why a failed or stalled card is so under
its title; the terminal shows the same facts as the agent's state in its stall, the ✗ of its row and the board's alerts band, since a
row of text has no ring to draw.
GitHub objective choices are composer checkboxes in the browser and `/delivery`
choices or `--auto-fix` / `--auto-merge` flags in the terminal.
Images are attached to a message in the browser by pasting, dropping or picking
them in the composer (`POST /api/sessions/{id}/images`), and the transcript shows
them. A terminal has no clipboard image or drop target: there a message names an
image file with `@path`, the agent opens it with its read tool, and from then on
the image is carried, described and retired exactly like an attached one.
