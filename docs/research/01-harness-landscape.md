## 0. Summary of findings

1. **Parity is Claude Code's public contract.** Peers copy its conventions almost verbatim: `CLAUDE.md`/`AGENTS.md` plus path-scoped `.claude/rules`, `SKILL.md` skills, markdown+YAML subagents, hook events where exit code 2 blocks, `!` shell and `@` mentions, plan mode, worktrees, `/goal`, agent teams and fan-out workflows. Qwen Code ships agent teams, dynamic workflows, `/batch`, `/goal`, an auto-mode classifier and a `tool_search` bridge [89]; Copilot CLI reads `.claude/rules` [86]; OpenCode falls back to `CLAUDE.md` and `~/.claude/skills` [68]. Compatibility with `.claude/`, `AGENTS.md`, Agent Skills `SKILL.md` [97] and MCP buys the whole ecosystem.
2. **The tool surface has converged** on: Read (line-numbered, offset/limit, images/PDF), exact-string Edit (uniqueness + read-before-edit), Write, ripgrep Grep/Glob, Bash (timeout, background jobs, output spilled to a file), task list, ask-user, subagent, skill, MCP resources, LSP. Tool names double as the keys for permission rules, hooks and subagent tool lists in Claude Code [6], so copying the names copies the ecosystem. OpenAI models use a grammar-constrained *freeform* `apply_patch` instead [55][56].
3. **Edit reliability is still an open problem.** Across 47 Aider polyglot runs using the `diff` (search/replace) format, mean well-formed rate is 92.2% (min 64.4%, 9 runs below 90%); `whole` never exceeded 49.3% (best run: Grok 3 Mini Beta, high; different models, so not a controlled comparison) [72]. A hash-anchored line-edit format is reported to add 5-14 points across 15 models and 10x for the weakest [94][52] (S); but a bash-only 100-line agent now exceeds 74% on SWE-bench Verified [91], so elaborate ACI tooling pays mostly for weaker models.
4. **The real permission boundary is the OS sandbox plus an egress proxy, not pattern rules.** Claude Code's own docs say `Bash(curl *)` denies miss `/usr/bin/curl` and `sh -c` [7]; humans approve 93% of prompts [37]; sandboxing cut prompts 84% [38]; the auto-mode classifier reads user messages and tool calls but never tool results [8][37]. Codex ships bubblewrap+seccomp/Seatbelt, a Starlark exec policy with unit-test examples, and an `auto_review` subagent [54][58][59].
5. **Context management**: auto-compaction triggers range from 50% of the window (Gemini CLI default) to about the limit (Claude Code, Codex) [81][29][103]; every serious harness clears or masks old tool output before summarizing [30][69][81]; JetBrains found masking matches LLM summarization at about half the cost [92]; providers now offer server-side compaction (Anthropic `compact-2026-09-04`, OpenAI `context_management`) [34][67].
6. **Caching is the hardest engineering surface.** Claude Code orders tools -> system -> project context -> conversation, appends every change as a message/`<system-reminder>`, defers MCP tools behind ToolSearch, lets forks (not subagents) reuse the parent's cache, staggers workflow siblings by 5 s and scopes cache per machine+directory [1][5]. Yet 63 changelog entries in 2026 mention prompt-cache behaviour (43 of them "Fixed ...", 33 in Aug-Sep alone) [47], and Anthropic's April postmortem ties usage-drain reports to a thinking-cache bug [39].
7. **Provider facts that shape a swarm.** Anthropic: a cache entry exists only after the first response *begins*; `max_tokens: 0` pre-warms; lookback is 20 blocks; 4 explicit breakpoints [31]. OpenAI: routing by hash of the first ~256 tokens plus `prompt_cache_key`; about 15 requests/min per prefix+key before overflow to a cold machine; the key lifted one coding customer from 60% to 87% hits [63]. Codex prewarms over WebSocket (`generate=false`) and sends only deltas via `previous_response_id` [60].
8. **Multi-agent shapes**: isolated subagents; forks; peer teams (task list + mailbox); script-driven fan-out (Claude Code workflows: 16 concurrent by default, 1,000 agents/run [5]); orchestrator/worker/validator missions (Factory [82], Gas Town [99]); planner/worker fleets (Cursor, hundreds of agents, [S] [84]). Anthropic's C-compiler swarm: 16 agents, ~2,000 sessions, 2B input tokens, ~$20k, coordination by git lock files [41]. No harness documents a *shared* cache across heterogeneous agents; Claude Code subagents get a separate cache and a 5-minute TTL [1][3].
9. **Top complaint classes** (section 10): quota/cost blowups and silent cache misses [48][49][51][64]; regressions from default changes [39][50]; compaction losing rules or looping [70]; permission inheritance bugs in subagents [70][78]; silent truncation [64]; runaway memory in Node-based CLIs [53]; plus vendor churn (Roo Code archived, Kimi CLI archived, Aider dormant) [73][75][87].
10. **Sleipnir's opening** (section 14): treat the tools+system+project-context prefix as a shared, versioned, pre-warmed asset for all agents; keep per-role differences out of the prefix (identical `tools` array, restrict at runtime); run a global rate/budget governor aware that cache reads are cheap and (for most models) exempt from input-rate limits [31]; publish per-agent cache SLOs; use a durable event log instead of JSON files and tmux panes; ship as one static Go binary.

Design notes:
- Claude Code tool names are the exact strings used by permission rules, hook matchers, subagent `tools:` lists and skill `allowed-tools` [6]. Reusing them (`Read`, `Edit`, `Write`, `Bash`, `Grep`, `Glob`, `Agent`, `Skill`, `AskUserQuestion`, `TaskCreate`...) makes third-party hooks, skills and agents portable.
- Fewer schemas is a cache and quality feature: Claude Code drops Glob/Grep on Unix, defers MCP tools, and disables the Task/Todo tools on its newest models because "Claude keeps track of multi-step work without a written checklist" and the definitions cost context [6]. Codex's prompt says to skip the plan tool for roughly the easiest 25% of tasks and never write single-step plans [56]. Anthropic's tool guidance: consolidate tools, namespace them, offer a concise/detailed `response_format`, cap responses (Claude Code uses 25,000 tokens), and return actionable errors [44].
- Tool search is now an API primitive (`defer_loading`, `tool_reference`): 55K -> 8.7K tokens of definitions (about 85% less) and Opus 4 MCP accuracy 49% -> 74% in Anthropic's evals [45]; Qwen Code re-implements it client-side as a `tool_search` -> `tool_call` bridge that keeps the declared tool list byte-stable [89].

### 3.2 Edit formats: evidence and pitfalls

| Format | Used by | Evidence | Known pitfalls |
|---|---|---|---|
| Exact-string replace (`str_replace`) | Claude Code, OpenCode, Gemini `replace`, Crush `edit`, Anthropic editor tool | default of most harnesses; no benchmark of its own in the sources I read | whitespace/indent must match byte-for-byte; must be unique; needs a prior read; one user estimates 15-20% first-try "String to replace not found" [52] (user report, not measured) |
| Search/replace blocks (Aider `diff`, `diff-fenced` for Gemini) | Aider | Polyglot top: GPT-5 (high) 88.0%, o3-pro 84.9%, Gemini 2.5 Pro (diff-fenced) 83.1%; format mean well-formed 92.2% (47 runs), 9 runs under 90%, min 64.4% [72] | malformed replies still ~8% on average; models ignore fencing rules (hence `diff-fenced`) [71] |
| Unified diff (`udiff`) | Aider (GPT-4 Turbo), Cline `apply_patch` | GPT-4 Turbo laziness benchmark 20% -> 61% (3x fewer lazy comments) [71]; Diff-XYZ: udiff best for apply/anti-apply, search-replace best for generating diffs on large models (S) [93] | hunk headers/line counts brittle; Aider simplified format ("familiar, simple, high level, flexible") [71] |
| Envelope patch (`apply_patch`, V4A-like) | Codex, OpenCode, Cline SDK | Codex exposes it as a *freeform* tool with a Lark grammar and a lenient parser (accepts whitespace around markers; leniency was added for gpt-4.1) [55][56] | needs model training/prompting; not for auto-generated or bulk regex edits (Codex prompt says use scripting instead) [56] |
| Whole file | Aider `whole` | best `whole` run 49.3% (Grok 3 Mini Beta, high) vs 88.0% best `diff` (different models, not a controlled comparison) [72] | slow/expensive, truncation on large files |
| Hash-anchored lines ("hashline") | proposal + PoCs; not in a major harness | +5-14 pp across 15 models; weakest models up to 10x (Grok Code Fast 1: 6.7% -> 68.3% vs patch); ~20% fewer output tokens (S) [94]; Claude Code request closed "not planned" [52] | one benchmark by one author (S); needs numbered/hashed read output |
| Symbol-level (LSP) edits | Crush | `lsp_replace_symbol`, `lsp_rename` recommended over text edits for whole-function edits and renames [80] | needs a running language server |
| Architect + editor split | Aider | o3 (high) architect + gpt-4.1 editor 78.2% at $17.6 vs o3 (high) alone 81.3% at $21.2 [72] | extra hop; editor formats `editor-diff`/`editor-whole` [71] |

Mitigations worth copying: Crush retries a whitespace-normalized whole-line match, re-indents `new_string`, and appends a "verify the result" note [80]; Claude Code lets an edit succeed on a file that changed since the read if `old_string` still matches exactly once, and counts `cat`/`sed -n`/`grep` on one file as a read [6]; Gemini's `replace` carries an `instruction` field describing intent [81]; OpenCode's prompt warns never to include the `N: ` line prefix in `oldString` [69]. Encoding traps: Claude Code's PowerShell tool wrote UTF-16LE with `>` before v2.1.214 [6]; Codex's prompt says "default to ASCII" [56]; checkpoints skip symlinked and hard-linked files [14]. Research context: SWE-agent's ACI (windowed viewer, flake8-gated edit, summarized search) beat a shell-only baseline by ~10.7 points on SWE-bench Lite in 2024 (S) [91]; LangChain moved a deep-agent from 52.8% to 66.5% on Terminal-Bench 2.0 by changing only the harness (self-verification loop, context injection, loop detection) (S) [95].

### 3.3 Shell, background processes, output limits

- Claude Code: default timeout 2 min (`BASH_DEFAULT_TIMEOUT_MS`), ceiling 10 min; on timeout the command is *moved to the background* (unless it starts with `sleep`) with a task ID and output-file path; `cd` persists only inside the project/added dirs, env vars never; output streams to a file (5 GB kill), inline up to ~30,000 chars for valid results (~10,000 for failures, head+tail), larger results become a session-dir file plus a 2,000-char preview; exit code 1 counts as benign for grep/rg/find/diff/test; optional memory cgroup cap (`CLAUDE_CODE_TOOL_MEMORY_LIMIT`, Linux) [6].
- Codex: PTY sessions; `yield_time_ms` default 10 s (250-30,000), `max_output_tokens` default 10,000, `write_stdin` polls up to 5 min (`background_terminal_max_timeout`); config `tool_output_token_limit`; `shell_environment_policy` filters the child env [56][54].
- OpenCode: truncates at 2,000 lines / 50 KB, writes the full output to a file (7-day retention) and returns a preview + hint [69]. Crush: commands running over 1 minute auto-move to the background (`auto_background_after`); the truncation marker names the file holding the full output [80]. Gemini: `is_background`; optional LLM summarization of shell output with a token budget; `tools.truncateToolOutputThreshold` [81].
- Long-running watchers: Claude Code `Monitor` streams each stdout line (or WebSocket frame) into the conversation with a 5-30 min deadline [6]; Codex `wait_for_environment`/`sleep` handlers exist [56]. Pi ships no background bash at all [98].

### 3.4 Search, read and code intelligence

- Claude Code, Codex, OpenCode, Crush: agentic ripgrep, no index. Aider: tree-sitter repo map ranked by a graph algorithm, default `--map-tokens 1k`, expands when no files are in chat [71]. Copilot CLI: `tgrep` trigram index for large monorepos [86]. Cursor: own embedding index; semantic + grep raised answer accuracy 12.5% on average (6.5-23.5% by model) (S) [84]. Windsurf: RL-trained "Fast Context" subagent doing 8 parallel tool calls per turn (S) [100].
- LSP: Claude Code exposes `LSP` only when a code-intelligence plugin is installed (definitions, references, hover, symbols, call hierarchy, post-edit diagnostics) [6][23]; OpenCode's `lsp` tool is experimental [68]; Crush ships `lsp_definition/references/rename/replace_symbol/call_hierarchy/symbols/restart` and `diagnostics` [80]; Codex has an open request (#8745) [64].

### 3.5 Plan, ask-user, subagent conventions

- Plan mode is a tool the *model* can call (`EnterPlanMode`/`ExitPlanMode`, Gemini `enter_plan_mode`/`exit_plan_mode{plan_path}`), which avoids a cache-breaking mode switch [1][46][81]; Claude Code re-injects the written plan file from disk after compaction [2].
- Ask-user is structured multiple choice with a free-text "Other"; Claude Code can auto-continue after 60 s/5 m/10 m so unattended runs never block (`askUserQuestionTimeout`) [6]; permission prompts never auto-resolve.
- Subagent results return as the final message only (plus a token/duration trailer); Claude Code scans that report for instruction-shaped text and prefixes a "harness:" marker line when found [3].

### 6.3 What silently breaks caching (each item was a real bug or documented trap)

1. **Tool-definition drift**: MCP connect/disconnect without tool search, plugin MCP servers, adding/removing a deny rule, LSP reconnect (fixed v2.1.235: "whole-prompt-cache invalidation"), Remote Control attaching mid-session re-sent the Bash tool definition (2.1.257), a forked worker adding `EnterWorktree` to the tool block (2.1.267), `ScheduleWakeup` definition changing across `--resume` when the account entered usage overage (2.1.248) [1][47].
2. **Model/effort/mode knobs**: each model has its own cache; effort changes invalidate on most models; fast mode adds a cache-key header; a skill with `model:` frontmatter is a model switch for that turn [1].
3. **System-prompt drift**: OAuth token refresh re-rendered tool definitions roughly hourly (2.1.248) and in telemetry-off sessions (2.1.259); per-machine values (auto-memory path, cwd, OS, git status) scope the cache to one machine+directory [1][47].
4. **History rewriting**: compaction; tool-result clearing; image eviction in batches (screenshot-heavy sessions missed every turn once images hit the cap, 2.1.257); a restored memory file's "age note" changing after compaction/resume (2.1.275); resumed history differing after a restart during a permission prompt (2.1.281); attachments re-rendered on resume (2.1.277); SessionStart hook output changing the first message after `/clear` (2.1.277); blocking Stop hooks dropping the turn's reasoning (2.1.259); output-limit cut-off plus auto-resume, and interrupt-mid-thought then resume (2.1.269) [47].
5. **Thinking handling**: Anthropic's own bug sent `clear_thinking` with `keep:1` on every turn after an idle threshold (shipped Mar 26, fixed Apr 10, v2.1.101), dropping thinking, missing the cache and draining limits [39][33].
6. **Idle/TTL**: default 5-minute lifetimes; users report the main-conversation TTL being cut from 1 h to 5 min in early March 2026 (S) [104]; resuming after 1-10 idle days re-caches 500-800K tokens against the 5-hour and weekly quotas (#95222) [49]; at ~950K context with four concurrent sessions the cache repeatedly collapsed to the ~38.7K system prefix every 33-61 s, suspected eviction under capacity pressure (#85326, open, stale) [48].
7. **Serialization nondeterminism**: JSON key order (docs name Go), timestamps or dynamic values early in the request, tool/response-schema edits and tool re-ordering, stray whitespace [31][63].
8. **Gateways**: a proxy that strips `cache_control` while returning success bills the whole history uncached every turn; converting block-form system content to a string drops the marker; not forwarding `anthropic-beta` breaks 1-hour TTL; not forwarding `tool_reference` disables tool search [1][17].
9. **Routing/capacity**: OpenAI overflow above ~15 RPM per prefix+key; caching is best-effort [63].
Meta-signal: 63 changelog entries in 2026 mention prompt-cache behaviour, 43 are fixes, 45 (33 fixes) landed in Aug-Sep alone [47]; Anthropic engineers reportedly alert on cache hit rate and treat <90% as critical (S) [46]. Cache correctness needs tests, not vigilance.

### 6.4 Numbers and an illustrative swarm calculation

- Claude Code enterprise averages: ~$13 per developer per active day, $150-250 per month, <$30/day for 90% of users [16]; sample `/usage` line "91% of input tokens from cache" [16]. Anthropic C-compiler swarm: ~2B input + 140M output tokens for just under $20,000 over ~2,000 sessions [41]. Multi-agent research uses ~15x chat tokens (4x for single agents) [40].
- OpenAI: TTFT up to 80% lower (67% at 150K+ tokens) and input cost up to 90% lower; Flex + extended retention + key gave +8.5 points of hit rate and -23% input cost over Batch [63].
- **Illustrative (my arithmetic from list prices in [31], not a measurement):** a 50K-token shared prefix (tools + system + CLAUDE.md + repo map) started by 30 agents. Sonnet 5.5 ($2 base, $2.50 5-min write, $0.20 read per M): 30 cold writes = $3.75; one write plus 29 reads = $0.125 + $0.29 = $0.415 (about 9x cheaper). Opus 5.5 ($4 base, $5 write, $0.20 read): $7.50 vs $0.54 (about 14x). Reads also skip the input-rate limit, which is what lets 30-50 agents start together. This covers only first-turn prefix cost; each agent's own history is a separate, per-agent cache line.
- Third-party fan-out measurements (S, unreplicated): 2.6-5.9x the input tokens of the same work run sequentially, and ~436K tokens of fixed overhead per Claude Code subagent (initial context load plus the cache write on its final turn) [102].

### 7.2 Coordination patterns and evidence

- Peer coordination substrates today are **files**: Claude Code mailbox/task JSON with file locks, Cline JSON board/mailbox, Anthropic's C-compiler swarm using `current_tasks/*.txt` lock files in git and "merge conflicts are frequent, but Claude is smart enough to figure that out" [4][74][41]. Codex adds a message board; Gas Town uses a git-backed ledger [56][99].
- Anthropic's own results: orchestrator-worker beat single-agent Opus 4 by 90.2% on an internal research eval, parallel tool calls cut research time up to 90%, early failure modes included spawning 50 subagents for simple queries (fixed with scaling rules in the prompt) [40]. Cognition's counterpoint: subagents lacking shared context make conflicting implicit decisions, so writes should stay single-threaded (S) [100]; Factory and Qwen follow that (serial workers, one writer) [82][89].
- Claude Code treats inter-agent messages as untrusted input: recipients are told the message came from another Claude session, no agent message can grant approval or change permissions/CLAUDE.md, and in auto mode the classifier reviews every outbound `SendMessage` [3][4][8][20].
- More agents do not help writers that share files: Claude Code says "two teammates editing the same file leads to overwrites" and "three focused teammates often outperform five scattered ones" [4]. Quantified conflict/coordination results are in `03-swarm-and-training.md` (A1, A4) and are not repeated here.

### 7.3 Known limits and cost behaviour above ~5 agents

- Token use scales linearly with active agents; idle teammates keep consuming until shut down [16]; agent view: N sessions = ~N x quota burn [19]; workflows warn at >25 agents [5]; the counting limit (20 subagents) is a fixed number that "tells Claude not to retry" rather than a budget [3].
- Agent teams: no nesting, no resume for in-process teammates, task status lags (teammates forget to mark completion, blocking dependents), teammates inherit the lead's permission mode and bubble every prompt to the lead, split panes need tmux/iTerm2 (not VS Code terminal, Windows Terminal, Ghostty), 5-minute cache TTL [4].
- Subagent depth and background rules changed several times in 2026 (depth 5 -> 1 -> 3; background subagents auto-denied prompts before v2.1.186) [3][6]: coordination semantics are still moving targets.
- Model-level swarms: Kimi K2.5 trains an orchestrator (PARL) to run up to 100 sub-agents over 1,500 tool calls for up to 4.5x lower latency (S) [88]; ordinary harnesses must supply that scaffolding themselves.

## 14. The ten most exploitable weaknesses (relative to a shared-cache swarm design)

1. **Every agent pays for its own prefix ("subagent tax").** Evidence: Claude Code subagents and teammates start from a fresh context with their own cache line and a 5-minute TTL; only forks read their parent's cache [1][3][4]; agent teams use ~7x the tokens of a standard session in plan mode [16]; a third-party measurement puts fixed overhead near 436K tokens per subagent and fan-out at 2.6-5.9x the tokens (S, unreplicated) [102]; Codex, OpenCode, Cline and Gemini start child agents as separate sessions, and I found no documented cross-agent prefix sharing in any of them [54][68][74][81]. Move: one versioned L0-L2 prefix shared byte-for-byte by all agents and prewarmed once; forks by default. My arithmetic (section 6.4): 50K prefix x 30 agents, $3.75 -> $0.415 on Sonnet 5.5, $7.50 -> $0.54 on Opus 5.5.
2. **Cache scope and TTL are second-class outside the main conversation.** Evidence: Claude Code requests the 1 h TTL only for the main conversation on a subscription within plan usage; subagents, workflows, teammates, forks and compaction default to 5 min, and API-key users get 5 min everywhere until they set `promptCacheTtl` / `subagentPromptCacheTtl`; the cache is scoped per machine and directory, and per-machine values sit inside the prefix [1]; users report the 1 h -> 5 min change (S) [104]. Move: per-layer TTL policy (1 h on L0-L1, 5 min on tails), keepalive pings for shared layers (Aider does this for its own cache [71]), and every machine- or agent-specific value moved out of L0-L2 into the first user message, as `--exclude-dynamic-system-prompt-sections` does [1].
3. **Fan-out stampede: parallel cold starts.** Evidence: an Anthropic entry is readable only after the writer's response begins, so N parallel identical prefixes all pay the write [31]; OpenAI overflows to a cold machine above ~15 requests/min per prefix+key [63]; Claude Code staggers only workflow siblings, by 5 s [1][5]; agent view and `/batch` run each session in its own worktree, hence a different directory and a different cache scope, so each pays its own prefix write [1][19][18]. Move: single-flight prefix writes behind a prewarm barrier, adaptive stagger, sharded cache keys.
4. **Compaction and tool-result clearing are per-session, cache-blind and lossy.** Evidence: each compaction is an "expected rebuild" [1]; API-side clearing invalidates the cache from the clearing point [33]; path-scoped rules and nested CLAUDE.md are summarized away and stated boundaries can be lost [2][8][12]; OpenCode shows too-early triggers, loops and forgotten rules (S) [70]; Claude Code's answer to thrash is an error message [30]. In a swarm, N agents pay N rebuilds at unsynchronized times. Move: swarm-level compaction policy (cache-aware clearing with `clear_at_least` [33]), a pinned never-compacted layer for rules, plan and brief, summaries stored as shared artifacts, compaction calls that reuse the agent's prefix [1]. Cache economics of compaction: `03-swarm-and-training.md` A3.2.
5. **No swarm-level cache observability; regressions ship silently.** Evidence: the `/usage` cache line and the status-line `prompt_cache` object cover the main conversation only [1][25]; 63 cache-related changelog entries in 2026, 43 of them fixes [47]; Anthropic's own thinking-cache bug drained limits from Mar 26 to Apr 10 [39]; users discover misses through quota burn (#95222, #85326, #16157) [48][49][51]. Move: per-agent, per-layer telemetry with likely-cause attribution from prefix diffs, golden-hash CI, runtime SLO alarms, the cache-diagnostics API where available [32].
6. **Count-based limits, no budget governor.** Evidence: the limits are counts - 20 concurrent subagents, 16 workflow agents, a warning above 25 [3][5]; Codex Desktop silently ignores `agents.max_threads` (#33447) [64]; ten background sessions burn quota ~10x as fast [19]; quota blowups dominate complaints [51][64]; no harness I read uses provider RPM-per-prefix limits [63] or the cache-read exemption from input-rate limits [31] when admitting work. Move: token-bucket governor keyed by provider, model and prefix; cache-aware admission (a warm start costs ~0.1x and does not count against input limits); dynamic concurrency; per-agent dollar caps.
7. **Coordination substrate is files and experiments.** Evidence: agent teams use mailbox JSON plus a file-locked task list, are experimental, cannot nest or resume in-process teammates, show status lag, and need tmux/iTerm2 for split panes [4]; Cline uses JSON board and mailbox files [74]; Anthropic's C-compiler swarm coordinated with lock files in git [41]; Gas Town runs on tmux and a Beads ledger [99]; Node/Python CLIs show multi-GB memory growth reports (S) [53]. Move: one Go process with an event-sourced log, leases, heartbeats, typed messages and crash-resume; agents as goroutines with bounded memory. Typed board, lease and mailbox shapes: `03-swarm-and-training.md` A4.5.
8. **Weak isolation and rollback for concurrent writers.** Evidence: Claude Code checkpoints do not cover Bash-made changes, subagent edits or external edits [14]; teams share one working tree ("two teammates editing the same file leads to overwrites") [4]; worktree fleets hit disk I/O limits (Cursor, S) [84]; merge conflicts are "frequent" in the C-compiler swarm [41]. Move: per-agent worktree or overlay, git-object snapshots that capture every side effect, single-writer leases, a merge queue with validators (Gas Town Refinery [99], Factory validators [82]). Conflict-rate baselines: `03-swarm-and-training.md` A4.2.
9. **Approval bottlenecks and permission-inheritance bugs at N agents.** Evidence: teammates inherit the lead's mode and surface every prompt in one terminal [4]; background subagents were auto-denied before v2.1.186 [3][6]; subagents ignored parent permissions in OpenCode (#7474, closed "not planned") and goose (#11778) [70][78]; users approve 93% of prompts and the auto-mode classifier misses 17% of real over-eager actions [37]. Move: one policy engine with agent identity, child rules = a subset of the parent's by construction, sandbox first, batched approvals ("allow this class for the swarm"), and a single cached reviewer prefix shared by all agents.
10. **Duplicated exploration and lossy handoff.** Evidence: subagents return only a final message [3]; no harness I read shares file reads, grep results or summaries across agents; Anthropic's research system saw duplicated work when task descriptions were vague [40]; Cognition reports conflicting implicit decisions without shared context (S) [100]; Factory needs a structured handoff plus a validation contract [82]. Move: a content-addressed artifact store (file digests, search results, summaries keyed by path+hash) that agents reference instead of re-reading; structured handoff records; planner-written briefs placed in L2. The shared-context debate is reconciled in `03-swarm-and-training.md` A1.1.

Design tension to resolve early: role-specific tool subsets versus cache sharing. Per-agent `tools:` lists are why Claude Code subagents cannot share a cache [1][3]; Sleipnir keeps one array and restricts at runtime [63][35].

Limits of the shared-cache thesis (test before betting the design on it):
- Each model has its own cache, and Anthropic isolates caches per workspace (per organization on Bedrock and Google Cloud), so sharing works only for agents on the same model and the same API workspace [31][1]; mixed-model swarms share less.
- Anthropic allows four explicit breakpoints and a 20-block lookback, so the layer count and the placement of moving breakpoints in long histories are bounded [31].
- Any provider-side change (TTL policy, routing, eviction under load) can erase the win without notice: users report a cache collapsing at ~950K context under four concurrent sessions [48] and a TTL change [104] - hence P0-26. Experiments to run before committing are listed in `03-swarm-and-training.md` ("Validation experiments to run before committing").
- Incumbents can respond: Anthropic already ships cache diagnostics, `max_tokens: 0` pre-warm, inline tool changes and mid-conversation system messages [31][32][35], and Claude Code already staggers and forks; the durable advantage is the swarm-level scheduler, governor and observability, not any single trick.
