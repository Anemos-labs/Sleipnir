# Building and contributing

## Toolchain

Use Go 1.25 or newer. The minimum version is declared in `go.mod`.
Dependencies are deliberately limited to the standard library and
`golang.org/x/{net,sys,term}`. Change module files only when needed.

```sh
go build ./...
go build -o bin/sleipnir ./cmd/sleipnir
go test -race -count=1 ./...
go vet ./...
gofmt -l cmd internal
```

The final command must print nothing. `scripts/check.sh` runs the broader
repository checks. See [Testing](TESTING.md) and [Repository setup](REPO-SETUP.md).

## Code conventions

- Keep provider-specific serialization in adapters.
- Return actionable tool errors as `tools.Result{IsError: true}`; use Go errors
  for harness failures.
- Sort map-derived prompt content. Never insert clocks or random identifiers
  into stable prompt layers.
- Keep tool schemas and descriptions concise. Every agent sends the same tool
  list; enforce restrictions through permissions.
- Protect shared state explicitly. Avoid mutable globals.
- Route writes through permissions, leases, checkpoints, and stale-read checks.
- Use the event log for usage and progress shown by the UI.
- Keep command help and tables readable in an 80-column terminal.

## Tests

Use temporary directories and isolated homes. Test observable behavior,
cancellation, hostile input, and concurrency. Synchronize concurrent tests with
barriers; use timeouts as hang guards, not performance assertions.

Platform tests must account for symlinks, case-insensitive filesystems, CRLF,
process semantics, and unavailable tools. Do not hide an implementation failure
by weakening an acceptance test.

## Terminal changes

Run changed screens in a real terminal and inspect their colors and layout:

```sh
scripts/look.sh /tmp/menu.png --cols 80 --key Down -- sleipnir login
node scripts/svg2png.mjs docs/media/chat.svg /tmp/chat.png --at 2
```

Open the PNG. Test narrow windows, resize, cancellation, and approval prompts.
A text snapshot cannot verify contrast. `scripts/look.sh` requires tmux,
util-linux script, Node, and Playwright Chromium; it uses a temporary home.

Recordings used as test fixtures are generated by `scripts/record-demo.sh`.
Label scripted model output as such. Do not use stale recordings to describe
the current interface.

## Changing prompt bytes

Prompt changes affect cache reuse. Review golden diffs before accepting them.

1. Update the relevant golden test intentionally.
2. If `kv.Render` changes output for the same stack and options, bump
   `kv.RendererVersion` and append the reported digest to `renderHistory`.
3. Describe the scope and cost of the change in `CHANGELOG.md`. Run
   `sleipnir sim` when assessing a policy change; identify its assumptions.
4. Check the final provider payload, including message boundaries and replayed
   output items. An internal hash is not a provider cache key.

## Documentation

Describe current behavior, configuration, invariants, and limitations.
Use timeless, impersonal language. Keep session narratives, handoffs, personal
notes, and unsupported performance claims out of the repository. Git records
implementation history; the changelog records concise release changes.
